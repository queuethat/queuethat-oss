# supabase/

The database is the application. Read the [architecture overview](../docs/architecture/README.md)
first; these are the conventions for working in this directory.

## Layout

- `migrations/`: ordered SQL, immutable once merged. A new file must sort last: name it with the
  current UTC time to the second (`$(date -u +%Y%m%d%H%M%S)_<name>.sql`).
- `tests/`: pgTAP. Every file starts `begin; \ir ../helpers/_setup.psql` and ends `rollback;`.
  `helpers/_setup.psql` holds helpers and factories (`.psql` so pg_prove skips it);
  `helpers/_generated.psql` and `rls/matrix.test.sql` are generated by `pnpm db:compile-tests`.
- `seeds/`: demo data for local development and CI only.
- `functions/`: Edge Functions (Deno). One exists only when it adds a capability the database
  cannot have: secrets, outbound I/O, CAPTCHA.
- `security-definer-allowlist.txt`: every `SECURITY DEFINER` function; `anon` marks the ones a
  guest without a session may call.

## Schemas

`app` base tables (authenticated only, RLS) · `api` RPCs, enums and return types (anon + authenticated)
· `private` helpers (never exposed) · `ops` cron jobs (never exposed).

## Writing a migration

- Tenant table: `org_id uuid not null`, composite foreign keys to parents (`(org_id, parent_id)`), trigger
  `private.forbid_org_change`, RLS on, one policy per command calling
  `(select private.has_role(org_id, location_id, 'staff'|'manager'|'admin'|'owner'))` or
  `(select private.is_device(org_id, location_id))`, audit trigger `private.audit_row` for config.
- Then add a fixture row to `tests.create_world()` and an entry to `tests/rls/matrix.yaml`.
- Functions: `security definer set search_path = ''`, fully qualified names, `COMMENT ON FUNCTION`
  before relying on it, explicit `revoke ... from public` and grants. Add definers to the allowlist.
- Errors: `raise exception '<code>'` (P0001), code listed in `packages/domain/src/errors.ts`.
  Permission failures use errcode `42501`. Unknown or foreign ids raise `not_found` (no existence leak).
- Visits: call `private.set_actor(kind, actor_id, action, reason, payload)` before every insert or update.
  The guard trigger enforces `app.visit_transitions`; the event trigger writes `visit_events`.
- Mutating RPCs are idempotent: anon joins on `visits.idempotency_key`, staff RPCs on `app.idempotency_keys`.
- Expand/contract only: old PWA bundles on TVs and kiosks run for weeks.
- pg_cron jobs run while migrations are applied, on a reset too. When a migration changes two
  tables that one statement of a job also uses, alter them in the order that statement locks them
  (its target table first, then the tables it reads). Otherwise the two can deadlock: `ops.enqueue_appointment_reminders` inserts into
  `notifications` while reading `guest_contacts`, and a migration that altered `guest_contacts`
  and then `notifications` lost to it in CI. `scripts/retry-on-deadlock.sh` reruns a reset that
  fails this way, and the self-host migrate step does the same.
- A migration that redefines an existing function copies the body from the latest migration that
  defines it and says so in a comment (`-- redefines private.join_core from <file>`).
  `scripts/check-redefinitions.mjs` fails the build when that source is stale, so two changes
  cannot silently drop each other's fixes.

## Extension hooks

A deployment that runs code of its own (a hosted service) plugs into tenant functions through
hooks: `private.ext_*` functions that do nothing here and that a tenant function calls at one
fixed point. The deployment replaces a hook's body in its own migration and never redefines the
tenant function, so changes made here keep reaching it.

| Hook | Called by | Here |
| --- | --- | --- |
| `private.ext_entitlement(org, key)` | `private.entitlement`, between the org override and the default | null |
| `private.ext_is_blocked(org, phone, email)` | `private.is_blocked` | false |
| `private.ext_support_grant(org)` | `private.support_grant` (so `private.has_role` for non-members) | no grant |
| `private.ext_bills_shared_sms(org)` | `private.channel_missing`: clears `platform_requires_billing` | false |
| `private.ext_report_incident(org, kind, title, description, detected_at, categories, key)` | `api.report_incident` when the business asks to tell the platform | null: a plain log entry |
| `private.ext_support_context(org)` | `api.contact_support`: extra facts in the request and email | `{}` |
| `private.ext_purge_keep_tables()` | `ops.purge_deleted_orgs`: tables to leave alone | none |
| `private.ext_price_changed(org, notification, old, new)` | `api.apply_provider_price` when a quoted cost changes | nothing |
| `private.ext_send_refusal(org, channel, reserved)` | `api.reserve_send`: refuses a paid send before anything is counted | null |
| `private.ext_send_reported(notification, org, channel, status, cost, segments)` | `api.report_outbox_result` after each report on a claimed row | nothing |

Rules: a hook's name, arguments and return type never change, and no migration here redefines a
hook once it exists (that would overwrite a deployment's body). Add a new hook rather than change
one. Each hook's `COMMENT ON FUNCTION` starts with `Extension hook:` and states its contract;
`tests/structure/extension_hooks.test.sql` checks the shapes.

### Edge Function extension files

Two functions have one file a deployment replaces with its own copy, for a sender that is the
deployment's rather than a business's (`provider_settings.mode` `platform`):

| File | Export | Here |
| --- | --- | --- |
| `functions/dispatch-notifications/extensions.ts` | `sharedSender({ env, functionsUrl })`: builds the channel for an org in mode `platform` | undefined: such sends end as `suppressed: channel_disabled` |
| `functions/provider-webhook/extensions.ts` | `extensionRoutes({ rpc, env })`: extra `/provider-webhook/<name>/<endpoint>` routes with their verifier, handler and secrets | none |

A built-in provider of the same name always wins. A verifier may name `storedFormKeys`: the only
form fields kept in the stored event, which must carry no guest phone number or text (I-13).

## Test helpers

`tests.create_world()` builds org A (owner, admin, manager, staff, display, kiosk) and org B
(`other_owner`). `tests.act_as('staff')`, `tests.as_anon()`, `tests.as_user(uuid)`,
`tests.as_device(...)`, `tests.as_service()`, `tests.as_postgres()`. `tests.id('queue_a')` names
fixtures; `tests.new_visit(name, queue)` creates a waiting visit. Never use SAVEPOINT rollbacks
around pgTAP calls (they roll back pgTAP's counters); use `tests.catches` / `tests.probe`.

A deployment with tables and actors of its own adds to these without editing them: its own
`tests/helpers/_extensions.psql` (in place of the empty one here) defines
`tests.create_world_extensions()`, which `tests.create_world()` calls last, and a
`tests/rls/matrix.<name>.yaml` next to `matrix.yaml` lists its tables, extra actors and any actors
it adds to existing tables (`allow_extra`). `pnpm db:compile-tests` reads both.
