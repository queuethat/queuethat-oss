# API v1

A small REST API for your own software: read queues and visits, add guests, call and serve them,
open and close queues. It is the database's own functions behind PostgREST, so there is nothing
else to host. Create keys in **Admin → API keys** (owners and admins).

The machine-readable description is [`openapi-v1.json`](openapi-v1.json) (Swagger 2.0 from
PostgREST; regenerate with `pnpm openapi:v1`, which `--check` verifies).

## Calling it

Every function is a **POST** to `/rest/v1/rpc/<function>` (never GET: GET runs read-only, and
every call charges the rate limit). Three headers:

| Header | Value |
| --- | --- |
| `apikey` | The project's public (publishable) key. It only lets the request reach the API. |
| `Content-Profile` | `api_v1` |
| `X-API-Key` | Your key, `qk_live_<8 hex>_<32 hex>`. Shown once when created; only a hash is stored. |

```sh
curl -X POST "$QM_API_URL/rest/v1/rpc/list_queues" \
  -H "apikey: $QM_PUBLIC_KEY" -H "Content-Profile: api_v1" \
  -H "X-API-Key: $QM_KEY" -H "Content-Type: application/json"
```

```json
[{"id":"…","location_id":"…","name":"Walk-ins","state":"open","accepting":true,
  "waiting_count":0,"eta_state":"next","eta_low_minutes":0,"eta_high_minutes":5}]
```

Send arguments as a JSON body named after the parameters, e.g. `{"p_visit_id": "…"}`.

## Scopes

A key holds one or more scopes and may be limited to some locations. A function outside the key's
scope fails with `insufficient_scope`; a queue or visit outside its locations is `not_found`.

| Scope | Allows |
| --- | --- |
| `queues:read` | `list_queues`, `get_queue` |
| `visits:read` | `list_visits`, `get_visit` |
| `queues:write` | `set_queue_state` |
| `visits:write` | `create_visit`, `transition_visit` |
| `analytics:read`, `webhooks:manage` | Reserved; no v1 function uses them yet. |

## Limits and errors

600 requests a minute per key. A request that fails is rolled back with its rate-limit charge, so
only successful calls count. Errors are HTTP 400 with the code in `message`:

```json
{"code":"P0001","details":null,"hint":null,"message":"unauthorized"}
```

| `message` | Meaning |
| --- | --- |
| `unauthorized` | Missing, malformed, unknown, wrong, revoked or expired key (all look the same). |
| `insufficient_scope` | The key lacks the scope this function needs. |
| `rate_limited` | More than 600 successful requests this minute. |
| `not_found` | Unknown id, or outside the key's locations. |
| `invalid_input` | A bad argument (unknown status or action, missing idempotency key). |
| `stale_visit` | `p_expected_version` is not the visit's current version; reread and retry. |
| `illegal_transition` | The action is not allowed from the visit's state. |
| `queue_not_accepting`, `capacity_reached` | The queue is closed, paused or full for new guests. |

Guest names and contact details are never returned by v1.

## Functions

Types: a **queue** is `{id, location_id, name, state, accepting, waiting_count, eta_state,
eta_low_minutes, eta_high_minutes}`; a **visit** is `{id, queue_id, ticket, status, party_size,
joined_at, called_at, serving_at, finished_at, updated_at}`.

| Function | Arguments | Returns |
| --- | --- | --- |
| `list_queues` | none | queues the key may see |
| `get_queue` | `p_queue_id` | a queue |
| `list_visits` | `p_queue_id`, optional `p_status` (array), `p_updated_after`, `p_limit` (default 100, max 500) | visits, oldest change first |
| `get_visit` | `p_visit_id` | a visit |
| `create_visit` | `p_queue_id`, `p_service_id`, `p_name`, `p_phone_e164`, `p_email`, `p_party_size`, `p_idempotency_key` | the visit; repeating the key returns the same visit |
| `transition_visit` | `p_visit_id`, `p_action`, `p_expected_version`, `p_idempotency_key`, optional `p_reason` | the visit |
| `set_queue_state` | `p_queue_id`, `p_state` (`open`, `paused`, `closed`) | the queue |

Page `list_visits` by passing the last row's `updated_at` as `p_updated_after`. The bound is
inclusive, so skip rows you already have by id; nothing is missed.

```sh
curl -X POST "$QM_API_URL/rest/v1/rpc/set_queue_state" \
  -H "apikey: $QM_PUBLIC_KEY" -H "Content-Profile: api_v1" \
  -H "X-API-Key: $QM_KEY" -H "Content-Type: application/json" \
  -d '{"p_queue_id": "…", "p_state": "paused"}'
```

For webhooks (events sent to you) see the [n8n guide](../integrations/n8n.md).

## Versioning policy

- v1 changes only additively and compatibly. Existing functions keep their exact arguments and
  return types; the pgTAP test `supabase/tests/api/v1_signatures.test.sql` snapshots them and fails
  any change. New behaviour is a new function or, if it cannot be compatible, `api_v2`.
- Adding a function or a defaulted trailing argument still updates the snapshot in the same PR, so
  it is a visible, reviewed decision. Adding a field to a returned type is a v1 change too; clients
  should ignore fields they do not know.
- A breaking change ships as `api_v2` next to v1, and v1 keeps working for at least 6 months after
  v2 is announced.
- A deprecated function is announced in this file and in the release notes, and its description in
  `openapi-v1.json` is marked deprecated, for the whole overlap.
