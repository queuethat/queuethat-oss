# apps/web

One React + Vite SPA serves every surface: the guest join page (`/q/:slug`), the guest status page
(`/v/:token`), the staff console (`/staff`), the admin console (`/admin`), the TV display
(`/display`) and the kiosk (`/kiosk`). Read the [architecture overview](../../docs/architecture/README.md)
first; these are the conventions specific to the web app.

- **Routing**: TanStack Router file routes in `src/routes`. Layouts sit on real segments
  (`routes/q/route.tsx`, `routes/staff/route.tsx`); TanStack `(group)` folders cannot hold layouts.
  New screens are new files. `/q`, `/v`, `/display` and `/kiosk` paths are frozen.
- **Data**: each feature keeps its access in `src/features/<area>/api.ts`: one query-options factory
  and one hook per RPC or table read. Screens import hooks; they never call `supabase` directly.
  `supabase.rpc()` targets the `api` schema; config tables use `supabase.schema('app').from(...)`.
  Live screens use `useLiveQuery` and never subscribe to realtime themselves.
- **Rules from the database**: render buttons from `allowed_actions` / `guest_actions`, and the ETA
  from `eta_state` via `formatEta`. Show "as of" from the server's `as_of`, never a local countdown.
- **Errors**: map with `errorCode()` from `@qm/domain`; switch on the code, never on message text.
- **UI**: components from `@qm/ui` only (no raw `<button>` in features), every string via `t()`,
  48 px minimum targets, `ConfirmDestructive` or undo for destructive actions, WCAG 2.1 AA (axe clean).
  The design system is described in [DESIGN.md](DESIGN.md) and shown live at `/dev/ui`.
- **Budget**: guest routes have a gzip JS budget checked by `pnpm build`. Don't import the full
  Supabase client or heavy libraries into `/q` or `/v` without checking it.
- **Platform pages**: a new `/platform/...` page without a path parameter or guard of its own goes in
  the registry in `features/platform/pages.tsx` (served by the one code-split `/platform/$` route),
  not a new file route: every file route adds bytes to the guest root chunk.

- **Extensions**: a deployment can add admin pages (served at `/admin/x/<path>`, optionally with a
  nav entry) and staff or admin banners without editing this app. It builds with
  `QT_WEB_EXTENSIONS=<path to its module>`, a module exporting `extensions` of the `WebExtensions`
  type in `src/extensions/types.ts`; `scripts/extensions.ts` swaps it in for the empty
  `src/extensions/installed.ts`. This repository installs none (run a deployment's module locally
  with `QT_WEB_EXTENSIONS=<path relative to apps/web> pnpm dev`). Extension pages and banners load
  only when shown, so they never reach the guest bundle. Slots (`ExtensionSlotProps`) are named
  places inside shared screens (`limits.reached`, `integrations.top`, `onboarding.alerts`,
  `onboarding.live`): a deployment's component renders there, and an empty slot renders the screen's
  own content. `sharedSender: true` tells the SMS setup that the deployment offers a shared
  sender account. Adding a slot is an extension point: say so in the pull request, and never change
  the props of an existing one.

`src/routeTree.gen.ts` is generated by the router plugin. Commit it, never edit it.
